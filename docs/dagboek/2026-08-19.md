# Dagboek — 2026-08-19

## Doel van vandaag
Een data stream excluden moest tot nu toe met een rauwe `PUT` in Dev Tools. Vraag:
is daar een commando voor, of kan het in het ansible-playbook? Antwoord: allebei
gebouwd.

Zie [2026-08-18](2026-08-18.md) voor de verificatie dát het exclusion-mechanisme
werkt; vandaag alleen de bediening eromheen.

## 1. `scripts/cpm_exclude_stream.py` (nieuw)

CLI voor ad-hoc gebruik, alleen stdlib, in dezelfde stijl als
`create_kafka_topics.py`.

```bash
cpm_exclude_stream.py --insecure add logs-winlog.winlog-default --reason "ticket Y"
cpm_exclude_stream.py --insecure add '*-tst' --reason "alle test-streams"
cpm_exclude_stream.py --insecure list
cpm_exclude_stream.py --insecure check logs-nginx-prod
cpm_exclude_stream.py --insecure remove logs-winlog.winlog-default
```

`check` is de nuttigste toevoeging: het spiegelt de matchregels van de watcher
(exact / prefix / suffix / prefix+suffix), zodat je vóór het draaien van de cyclus
ziet wat een patroon raakt. Na `add`/`remove` print het script de vervolgstap.

Wildcards kunnen niet in een document-id; `*` wordt gecodeerd als `_STAR_`
(`*-tst` → id `_STAR_-tst`).

## 2. Ansible-taak `stream_exclusions.yml` (nieuw)

Declaratief beheer vanuit de inventory:

```yaml
cpm_stream_exclusions:
  - { pattern: "logs-winlog.winlog-default", reason: "ticket Y" }
  - { pattern: "*-tst", reason: "alle test-streams" }
cpm_stream_exclusions_prune: false
```

Uitrollen: `ansible-playbook -i inventories/<env> site.yml --tags exclusions`

Twee modi:
- **additief** (default) — exclusions die met het script of via Dev Tools zijn
  gemaakt blijven staan
- **prune** (`cpm_stream_exclusions_prune: true`) — inventory is leidend, al het
  overige wordt verwijderd

De taak draait ná `seed_data.yml` en vóór `registry_patch.yml`. Timestamp via
`lookup('pipe', 'date -u …')` omdat `site.yml` op `gather_facts: false` staat.

Let op bij `include_tasks`: de tag moet op de **include** in `main.yml` staan, niet
alleen op de taken in het included bestand — anders doet `--tags exclusions` niets.
Dat kostte de eerste testronde.

## 3. Ingest-pipeline `cpm-stream-exclusions-stamp` (nieuw)

Zodat een kale `PUT` in Dev Tools geen handmatige timestamp meer nodig heeft, staat
op `cpm-stream-exclusions` nu `default_pipeline: cpm-stream-exclusions-stamp`. Die
vult `updated_at` (huidige tijd, `strict_date_time_no_millis`, UTC) en `updated_by`
(`unknown`), beide met `override: false` — een expliciet meegegeven waarde blijft
dus staan.

Waarom een `date`-processor achter de `set`: `{{{_ingest.timestamp}}}` levert
nanoseconde-precisie, wat de `strict_date_optional_time`-mapping niet altijd
accepteert. De `date`-processor normaliseert naar `2026-08-19T13:00:23Z`.

Pipeline én index-setting worden door `stream_exclusions.yml` zelf neergezet, niet
via `cpm_index_dynamic_settings`. Reden: `indices.yml` draait vóór
`ingest_transform.yml` in `main.yml`, dus een `default_pipeline` die daar gezet
wordt zou naar een nog niet bestaande pipeline wijzen.

Getest: kale PUT → gestempeld; wildcard-PUT → gestempeld; PUT met expliciete
`updated_at: 2026-07-03T10:00:00Z` → waarde behouden.
